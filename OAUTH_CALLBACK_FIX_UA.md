# Battle.net → RaiderHub: відновлення callback, Site 4.6.4

## Причина

У `next.config.ts` адреса `/callback.html` була перенаправлена на `/guild/apply`. Маршруту `/callback` не було. RaiderHub використовує `https://lihvodruida.pp.ua/callback` як `OAUTH_REDIRECT_URI` та приймає результат через `lihvodruida://callback`.

## Що змінено

- Додано `/callback` і `/callback.html` з однаковою поведінкою. Прибрано редирект на форму гільдії.
- Сторінка автоматично пробує відкрити `lihvodruida://callback` через 120 мс. Якщо браузер блокує автоматичний перехід, залишається кнопка «Відкрити RaiderHub».
- `code`, `state`, `error` і `error_description` передаються через `URLSearchParams` зі збереженням декодованих значень. Адреса повернення фіксована; сторонні query-параметри не передаються.
- Порожній, дубльований або суперечливий результат не відкриває застосунок. Сторінка пропонує розпочати вхід повторно. Перевірка очікуваного `state` залишається в RaiderHub.
- Сторінка працює окремо від загального layout, React-гідратації, CMS і синхронізації гільдії. Її код і стилі локальні.
- Відповідь має `no-store`, `no-referrer`, `noindex` та CSP. Query прибирається з адресного рядка після читання; кнопка зберігає результат до закриття сторінки. Перезавантаження потребуватиме нового входу з RaiderHub.

## Оновлення на VPS

Розпакувати вихідний код у чинну директорію сайту, зберігши власні `.env` та `compose.override.yml`. У директорії сайту виконати:

```bash
make check
make deploy
```

Зміни набудуть чинності після збірки й перезапуску сайту. Самої заміни файлів без деплою недостатньо. Поточний Nginx із цього архіву вже передає ці шляхи контейнеру сайту.

У Battle.net Developer Portal залишити точний Redirect URI:

```text
https://lihvodruida.pp.ua/callback
```

Це та сама адреса, що в поточному `app/build.gradle.kts` RaiderHub. Для цього виправлення не потрібно змінювати Redirect URI або перевипускати APK. `/callback.html` відновлено для сумісності; його не потрібно підставляти замість поточного URI.

Після деплою перевірити обидві адреси без справжніх кодів авторизації:

```bash
curl --fail --include https://lihvodruida.pp.ua/callback
curl --fail --include https://lihvodruida.pp.ua/callback.html
```

Очікується HTTP 200, HTML із заголовком «Повернення в RaiderHub», `Cache-Control` з `no-store` та `Referrer-Policy: no-referrer`. Заголовка `Location: /guild/apply` бути не повинно. У браузері без query сторінка правильно попросить повторити вхід. Справжній вхід починати з RaiderHub, щоб застосунок зберіг очікуваний `state`.

## Перевірки

- `npm run typecheck` — успішно.
- `npm test` — 57 пройдено, 3 пропущено через відсутність парного Dashboard/PostgreSQL; помилок немає. Серед пройдених — 7 нових перевірок callback.
- `npm run check:content` — успішно.
- `npm run check:deploy` — 19 перевірок пройдено.
- `npm run build` — production-збірка Next.js 16.3.5 успішна; обидва callback-маршрути присутні.
- `npm run check:standalone` — успішний запуск production-сервера. Перевірено HTTP 200 обох адрес, відсутність редиректу, заголовки, невідображення OAuth-параметрів у HTML та доступність JS/CSS у standalone-пакеті. Інші інтеграційні й SEO-перевірки цього сценарію також пройдені.

Повний вхід у справжній Battle.net із поверненням на Android-пристрій тут не виконувався. Живий сервер не оновлювався; цей архів містить готове виправлення для деплою.
