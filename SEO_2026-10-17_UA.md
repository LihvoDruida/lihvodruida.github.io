# Лігво Друїда 4.4.0 — SEO публічного сайту

Оновлено саме сайт lihvodruida.pp.ua. Код дашборду, Discord-бота та правила очищення учасників не змінювались. Архів не розгортався на VPS під час роботи.

## Що зроблено

Для головної, гайдів, новин, адонів, гільдії, вступу й підтримки додано окремі заголовки, змістовні описи, абсолютні canonical та узгоджені Open Graph / Twitter-прев’ю. Заголовок бренду не дублюється. Базова ілюстрація має реальні розміри 1200×630. Є RSS-discovery, українська мова документа, навігаційні ланцюжки та структуровані дані WebSite, Organization, WebPage / CollectionPage / AboutPage і BreadcrumbList.

Матеріали CMS отримують індивідуальні title/description, Article або BlogPosting, автора, опубліковану й змінену дату, зображення та canonical. Якщо опис порожній, береться читабельний фрагмент тексту. Некоректна дата зміни не створює вигаданої свіжості. Дати також видимі читачу. У Markdown заголовок першого рівня перетворюється на підзаголовок, щоб сторінка мала один H1. Додано посилання на інші матеріали того самого розділу. JSON-LD безпечно екранує текст із CMS.

## Сторінка гільдії

Пошукові теми: українська гільдія WoW, гільдія World of Warcraft українською, Mistblossom Vanguard, гільдія EU Terokkar, рейди, Mythic+, вступ до гільдії.

Ключові теми використані в природному видимому тексті, без прихованих переліків запитів. Додано опис спільноти, напрямки спільної гри, посилання на заявку й гайди, відповіді про вступ, реалм і знайомство в Discord. Гільдія описана як Organization, а сторінка — як AboutPage. Не створюються вигадані вакансії, оцінки, рейтинги чи обіцянки розширеного результату FAQ.

Назва та реалм узгоджені з публічним знімком гільдії. При недоступності знімка залишаються перевірені налаштування спільноти: її назва, реалм, опис і Discord. Лічильники та рейдові дані не вигадуються. Опис, заголовок і розмітка доступні в початковому серверному HTML, навіть без JavaScript і при холодному збої дашборду. Поточні склад, прогрес, сезони й синхронізація продовжують працювати.

## Індексація

| Сторінки | Режим |
| --- | --- |
| /, /guides, /news, /mods, /guild, /guild/apply, /donate | Індексувати; власний canonical |
| Опубліковані /guides/[slug] та /news/[slug] | Індексувати; metadata та schema з CMS |
| /guild/applications | noindex у meta і HTTP-заголовку; не входить до sitemap |
| Відсутній або знятий із публікації матеріал | notFound, noindex; відсутній у sitemap/RSS |
| Службові JSON API | Не призначені для індексації; X-Robots-Tag та robots.txt |
| /site-api/v1/media/[hash] | Доступний для обкладинок; не заблокований robots.txt |

Статуси заявок не заборонені в robots.txt: пошуковик має прочитати їхній noindex. Це не механізм авторизації і не змінює доступ до сторінки.

Sitemap містить сім публічних сторінок і тільки опубліковані матеріали CMS, справжні lastmod статей та посилання на їхні зображення. Для сторінок без достовірного часу редагування дата не вигадується. При холодному збої CMS sitemap повертає 503 з Retry-After: 60 замість порожнього успішного знімка. Наявний короткочасний кеш зберігає попередні валідні дані за правилами синхронізації.

## Перевірки

- build:ci: typecheck, тести Node, перевірка контенту, тести деплою, production build та standalone — пройшли.
- Node: 48 тестів; 45 пройшли, 3 опціональні перевірки потребують зовнішнього fixture. Дві з цих інтеграцій окремо виконано з локальним дашбордом/PGlite: подання заявки та цикл draft/publish/edit/unpublish — 2/2.
- Production HTML на 10 сторінках: унікальні title/description, canonical, Open Graph, Twitter, українська мова, один H1, JSON-LD, breadcrumbs, noindex, 404. Перевірено також runtime-коди Google/Bing verification.
- Холодні збої гільдії та CMS: підтверджено збереження опису гільдії і коректний 503 sitemap.
- Chromium: гідратація, сторінка гільдії та історичні сезони на 320/390/1440 px, відсутність горизонтального переповнення; редагування відкритої статті та її зняття з публікації без повного перезавантаження, оновлення RSS/sitemap. Вигляд перевірено візуально.
- Усі інтеграційні запити проходили через ізольований тестовий транспорт; реальні заявки, Discord і база користувача не змінювались.

## Встановлення

1. Оновити файли саме /srv/lihvodruida-site, зберігши власний .env.
2. Виконати `make up`. Наявні перевірки інтеграції та rollback залишаються активними.
3. Перевірити https://lihvodruida.pp.ua/robots.txt, https://lihvodruida.pp.ua/sitemap.xml, сторінку /guild та одну опубліковану статтю.
4. У Google Search Console для своєї властивості подати sitemap.xml, перевірити /guild через URL Inspection та запросити індексацію оновленої сторінки. Це виконує власник у своєму обліковому записі; доступ до Search Console тут не надавався.
5. За потреби додати GOOGLE_SITE_VERIFICATION та BING_SITE_VERIFICATION до .env — лише виданий код, без meta-тегу — і перевідтворити контейнер. Підтвердження на головній читається під час виконання. Самі коди не є гарантією успішного підтвердження власності.

Якщо зовнішня перевірка деплою повертає Cloudflare challenge/403, скористатися наявною діагностикою інтеграції. SEO-файли не змінюють правила Cloudflare. Після деплою перевірити доступність сторінок, ресурсів і зображень для пошукових роботів у Search Console; не вимикати захист усього сайту заради перевірки.

SEO не гарантує конкретної позиції або миттєвої індексації. Для оцінки результату слід відстежувати покази, запити й переходи в Search Console після повторного обходу сайту.
