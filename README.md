# Лігво Друїда · сайт 4.1.0

Публічний сайт Next.js/Node.js, узгоджений із дашбордом 3.9.0. Гайди, новини, склад гільдії, рейдовий прогрес, розклад та заявки читаються з дашборда. Робочої Jekyll-версії, GitHub Pages-деплою й локального архіву складу немає.

Повний порядок переходу: [UNIFIED_INTEGRATION_2026-10-16_UA.md](UNIFIED_INTEGRATION_2026-10-16_UA.md).

## Конфігурація

```dotenv
SITE_URL=https://lihvodruida.pp.ua
DASHBOARD_URL=https://guild.lihvodruida.pp.ua
DASHBOARD_INTERNAL_URL=http://dashboard:3000
PUBLIC_SITE_BRIDGE_TOKEN=<той самий секрет, що в кореневому .env дашборда>
SITE_EDGE_NETWORK=mistblossom_edge
```

Потрібен URL-safe токен 32–256 символів; рекомендовано 64 hex-символи. Не додавати його в `NEXT_PUBLIC_*`. `DASHBOARD_URL` використовується для публічних посилань. Увесь обмін даними відбувається через обов’язковий `DASHBOARD_INTERNAL_URL`; автоматичного перемикання на публічний HTTPS немає.

Підготувати парні env можна скриптом із релізу дашборда:

```bash
python3 /srv/mistblossom/deploy/prepare-unified-env.py --site-dir /srv/lihvodruida-site
```

Він зберігає чинні значення, переносить перейменовані налаштування сховища, створює секрет за потреби та захищені резервні копії env. Різні вже задані токени або конфлікт налаштувань зупиняють підготовку.

## Запуск і перевірка

```bash
npm ci --no-audit --no-fund
npm run build:ci
npm start
```

Для VPS після оновлення дашборда:

```bash
make check
make deploy
curl --fail https://lihvodruida.pp.ua/api/bridge/status
```

`make deploy` збирає лише сайт, очікує healthcheck і перевіряє сумісність зв’язку з PostgreSQL. Якщо перевірка не пройшла, намагається повернути попередній здоровий образ. Це не відкочує БД або інший Compose-проєкт.

## Обмін даними

| Браузер / SSR | Дашборд |
|---|---|
| `/api/bridge/guild` | `/api/site/guild` |
| `/api/bridge/applications`, GET/POST | `/api/site/applications`, GET/POST |
| CMS-сторінки, RSS, sitemap | `/api/site/content?page=N`, контракт v2 |
| `/api/media/:sha256` | `/api/site/media/:sha256` |
| `/api/bridge/status` | `/api/site/status` |

Заявки надсилаються через власний домен, без cookies дашборда. Nginx має перезаписувати `X-Real-IP`; у production відсутня коректна адреса клієнта блокує надсилання. Ліміти дашборда рахують кожного відвідувача окремо.

Читання має обмежений кеш, об’єднання одночасних запитів і backoff. Заявки кешуються 15 с, останні підтверджені статуси при збої — до 2 хв. Склад кешується 60 с, останній підтверджений знімок процесу при збої — до доби з позначкою застарілості. Без підтвердженого знімка API повертає 503; старий YAML не підставляється. Склад і статуси оновлюються у фоні без перезавантаження сторінки.

CMS кешується 60 с, при збої останній підтверджений вміст може використовуватися до 5 хв. Знімок збирається з перевіркою однакової ревізії всіх сторінок. Холодний збій не перетворюється на успішну порожню бібліотеку або хибний 404 статті. Головна показує окреме повідомлення про недоступність бібліотеки.

Обкладинки віддаються через власний домен із перевіркою SHA-256 і лімітом 8 MiB. Статичні логотипи, ілюстрації, довідник професій, спільнот та авторських персонажів залишаються ресурсами сайту. Довідник професій не оголошується живими даними API. CurseForge має окремий чинний клієнт і власний серверний ключ.

## Тести

`npm run build:ci` включає типи, тести контрактів/кешування/заявок, контроль ресурсів, сценарії деплою з фальшивим Docker CLI, збірку і запуск справжнього production standalone з контрольованим upstream.

Для перевірки пари вихідних кодів:

```bash
PAIRED_DASHBOARD_ROOT=/srv/mistblossom/dashboard npm test
```

Цей сценарій виконує справжній route handler дашборда з контрольованими БД/Discord і звіряє байти валідатора заявки в обох проєктах. Живі повідомлення не надсилаються.
