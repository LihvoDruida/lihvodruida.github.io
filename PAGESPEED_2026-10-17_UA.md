## Реалізовано

- Прибрано зовнішній Google Fonts @import. Inter Latin/Cyrillic і шрифти
  банера завантажуються локально як WOFF2 з font-display:swap. Українські
  символи збережено; OFL-ліцензії включено. Збірка не звертається до Google.
- Мобільний фон банера: 2 026 751 → 17 334 байти (−99,1%); desktop — 67 426
  байтів. Вигляд, бічні порожні області, посилання /guild та згортання збережено.
- Головне зображення: адаптивні AVIF/WebP 640/960/1200 px, loading=eager,
  fetchpriority=high, явно задані розміри. Мобільний Chrome обрав AVIF 40 166
  байтів; серверне перекодування hero при першому відкритті більше не потрібне.
  Початковий OG-оригінал для соціальних мереж збережено.
- Логотипи мають 96/160/240 px варіанти з srcset/sizes. Наприклад, зображення
  160 px: Mistblossom — 7 466 замість 47 860 байтів, Варта — 4 572 замість
  32 550. Навігація використовує відповідний малий варіант.
- Рік immutable-кешу застосовано лише до зображень з хешем у назві. Новий
  контент отримує новий URL. Живі дані, заявки й CMS-медіа зберігають свої
  попередні правила актуальності та доступу.
- Перший екран головної сторінки передається через серверний Suspense до
  завершення запиту бібліотеки CMS. Матеріали залишаються серверним HTML;
  обробка помилок та актуалізація публікацій працюють.
- Декоративний starfield запускається після завантаження сторінки, малює
  до 24 кадрів/с на мобільному та до 30 на desktop, зберігаючи швидкість руху.
  Зменшено мобільний DPR, анімація зупиняється у прихованій вкладці та при
  ввімкненні reduced motion. На сенсорному екрані не малюється mouse spotlight.

Це окремий локальний тест 4.4.1 → 4.5.0 з однаковим контрольованим джерелом

Обсяг ресурсів зменшився на 85,1%. LCP discovery тепер проходить усі три
перевірки: початковий HTML, eager та high priority. Cache insight для
перевірених локальних ресурсів більше не показує втрат.

Обмеження: середовище локального тесту блокувало зовнішні Google Fonts та
аватари Blizzard; через мережеві помилки Best Practices обох локальних
запусків — 96. Це не означає погіршення публічного показника 100. Один запуск
не гарантує сталий бал; реальний VPS, Cloudflare, відвідувачі та CMS можуть
змінювати результат. Локальний LCP 3,39 с ще перевищує бажані 2,5 с.
Після деплою необхідно повторити саме публічний mobile PageSpeed.

Не видалялися поліфіли Next.js чи механізми синхронізації заради бала:
вхідний звіт мав TBT=0, а сумісність і актуальність даних необхідно зберегти.

## Встановлення

Розпакувати проєкт у /srv/lihvodruida-site, зберігаючи робочий .env та
локальні override-файли. Далі:

```sh
cd /srv/lihvodruida-site
make up
```

Міграція БД або зміни дашборда не потрібні. Архів перевірено локально;
на бойовий VPS цю версію ще не встановлено.

## Повторення перевірок та оновлення ресурсів

```sh
npm ci
npm run build:ci
```

Додаткова browser/performance перевірка потребує Playwright та Chromium у
середовищі тестування (як і наявний check:browser):

```sh
SITE_QA_CHROMIUM=/absolute/path/to/chromium \
SITE_QA_PLAYWRIGHT=/absolute/path/to/playwright/index.js \
SITE_QA_PERFORMANCE="$PWD/scripts/check-performance.cjs" \
node scripts/check-standalone.mjs
```

Для необов'язкового Lighthouse-вимірювання додати SITE_QA_LIGHTHOUSE_MODULE
з абсолютним шляхом до lighthouse/core/index.js та SITE_QA_PERFORMANCE_OUTPUT
з місцем для JSON. Порт 9227 має бути вільним. Production залежності не
містять Playwright/Lighthouse. Не запускати build під час браузерної перевірки.

Після заміни оригінального зображення:

```sh
node scripts/optimize-site-images.mjs
```

Комітити/розповсюджувати разом нові зображення, src/lib/site-assets.json та
оновлений src/app/guild-banner.css. Версія sharp зафіксована package-lock.
